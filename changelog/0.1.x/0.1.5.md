# 0.1.5 — 2026-07-27

## Added

- **Calendar-valid date filters** — `date_start`/`date_end` on `cpsc_search_recalls` now parse with `z.iso.date()` instead of a digit-shape regex, so `2026-99-99` and `2026-02-31` are rejected at input validation instead of reaching the upstream API ([#1](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/1)).
- **`invalid_date_range` error** — `date_start` later than `date_end` now throws a declared `ValidationError` naming both values instead of silently returning `no_results` ([#1](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/1)).
- **CPSC error-row rejection** — `CpscRecallService.fetchRecalls` now recognizes the one-row sentinel array CPSC substitutes for malformed requests (identifying fields null, upstream message in `Title`) and throws a non-retryable `serviceUnavailable` instead of crashing on `null.slice()` during normalization. Shared by `search`, `getByNumber`, and `getRecent` ([#1](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/1)).
- **`data_quality_notes`** — new array output field on all three tools recording upstream gaps (absent description, no hazard text, no product entries) observed directly from empty fields, with no judgement about the recall itself ([#3](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/3)).
- **`source_note`** — new string output field on all three tools stating that recall fields are relayed verbatim from CPSC, unedited and unverified, and that `cpsc_url` should be checked before a consumer-facing decision ([#3](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/3)).
- **Source-text framing** — `cpsc_get_recall.format()` renders relayed CPSC narrative (hazard, remedy, contact, description, injuries, retailers, image captions) as markdown blockquotes under `(CPSC source text)` headings, visually separated from server-authored guidance; `cpsc_search_recalls.format()` labels its per-record relayed block `CPSC source fields:` ([#3](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/3)).
- **`tests/services/cpsc-recall/cpsc-recall-service.test.ts`** — new service-level test file covering error-row rejection on the `search` and `getRecent` paths and a sparse-but-genuine record passing through untouched.

## Changed

- **`description` is nullable** — `cpsc_get_recall`'s output field is now `z.string().nullable()` instead of a normalized empty string, so recall `04084` (a genuine record with no upstream description) returns instead of failing output validation. `format()` renders `_Not provided by CPSC._` for the null, empty, and whitespace-only cases ([#4](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/4)).
- **`RawRecall.Description`** — retyped `string | null` to match observed upstream reality.
- **Manufacturer and importer render as separate roles** — `cpsc_get_recall.format()` splits the merged `## Manufactured By / Imported By` section into `## Manufactured By` and `## Imported By`, each shown only when populated; `cpsc_search_recalls.format()` emits separate `**Manufacturer:**` / `**Importer:**` lines and joins multiple orgs within a role with `; ` instead of `, ` (CPSC org names contain commas, which made the merged `, `-joined line unparseable) ([#5](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/5)).
- **`cpsc_search_recalls.format()` product list** — joined with `; ` instead of `, ` for the same comma-collision reason.

## Fixed

- **`cpsc_get_recall` returns recall `04084`** — previously failed output validation with "expected string, received null" ([#4](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/4)).
- **Impossible calendar dates no longer crash the search handler** — previously threw `null is not an object (evaluating 'r.RecallDate.slice')` when CPSC's sentinel row reached normalization ([#1](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/1)).
- **Manufacturer/importer attribution no longer collapses into one unparseable line** in `content[]` output ([#5](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/5)).
