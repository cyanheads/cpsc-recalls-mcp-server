# 0.2.0 — 2026-09-24

The first five Changed bullets break existing callers: error handling and paging signals on `cpsc_search_recalls` and `cpsc_get_recent` change.

## Changed

- **Zero matches on `cpsc_search_recalls` are an empty success, not the `no_results` error** ([#12](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/12)). `no_results` leaves the error contract; every success carries an `effectiveQuery` echo, and a zero-match result adds a `notice` naming which criterion to relax.
- **`cpsc_search_recalls` requires a search criterion** ([#11](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/11)). With no non-blank text filter and no date bound, it fails with `missing_criteria` before any upstream request; blank and whitespace-only filters count as omitted.
- **Text filters are capped at 500 characters** ([#18](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/18)). A longer value on any of the nine filters or the `hazard` alias is rejected as `-32602` before any upstream request; `tools/list` advertises `maxLength: 500`.
- **`truncated` equals `has_more` on both list tools** ([#9](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/9)). It no longer tracks `total_found > limit`, so final and exhausted pages report `truncated: false`; an offset past the last match returns an empty page with a `notice`.
- **List-tool pages stop at a 64,000-byte response budget** ([#13](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/13)). A page can return fewer than `limit` records, with `has_more: true` and a `notice` naming the offset to continue from; at least one record comes back whenever any remain.
- **`cpsc_get_recent` explains an empty window** in a new `notice`, suggesting a larger `days` or, at 365, `cpsc_search_recalls` date bounds ([#12](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/12)).
- **Advertised text describes behavior, not upstream mechanics** ([#10](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/10)). Tool descriptions, `.describe()` text, error `when`/`recovery`, and server `instructions` are rewritten; all three tools render the jurisdiction under one `CPSC jurisdiction:` label, and an upstream rejection reads `CPSC rejected the request: …`.
- **`cpsc_get_recall` rejects a malformed `recall_number` with both accepted forms spelled out** (`"25043"`, `"99003a"`) instead of the raw regex ([#10](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/10)).
- README tool reference and `docs/design.md` Superseded notes follow the new search and paging behavior; `CLAUDE.md`/`AGENTS.md` declare the gated release mode.

## Fixed

- **Multi-word text filters match every word, in any order** ([#16](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/16)). They matched only a contiguous phrase, so `title_search: "Graco crib"` found nothing; `%`, `_`, and `[…]` now match literally, and straight and curly apostrophes match each other.
- **Searches that map no upstream parameter include the newest recalls** ([#17](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/17)). A `hazard_search`-only search now sends `RecallDateStart=1970-01-01`, because the unfiltered CPSC collection lags filtered requests.
- **`cpsc_get_recent` header reads `(1 day)`**, not `(1 days)` ([#9](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/9)).
