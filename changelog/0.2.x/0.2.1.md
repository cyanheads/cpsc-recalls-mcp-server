# 0.2.1 — 2026-09-24

## Changed

- **`source_note` no longer calls recall fields verbatim or unedited** ([#14](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/14)). It now says they are CPSC record text with HTML markup and character codes converted to plain text; `cpsc_get_recall`'s quoted-block line adds that a backslash before a Markdown character is an escape.
- README capability notes and `docs/design.md` (Superseded notes, three Design Decisions rows) cover normalization, escaping, and the retry; the `CLAUDE.md`/`AGENTS.md` structure blocks list `markdown-escape.ts` and `normalize-text.ts`.

## Fixed

- **CPSC HTML markup and character references are converted to plain text in the service** ([#14](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/14)). `&amp;`, numeric references, and `br`/`p`/`td`/`tr` tags (cut-off ones included) no longer reach either surface, and text filters match the plain text, so markup such as `valign` no longer matches; unknown references and bare `&` stay as written.
- **`content[]` escapes Markdown in CPSC text on all three tools** ([#14](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/14)). Serial patterns such as `1HFVE05**K4000003` keep their asterisks, a line starting with a block marker such as `#`, `>`, `-`, or `1.` never opens a block, and a `cpsc_url` containing spaces renders as a working link; `structuredContent` stays unescaped.
- **Image and coordinated-recall addresses in `content[]` render as one working link** ([#21](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/21)). Spaces, `<>()`, and a trailing `.`, `_`, or `~` are percent-encoded; `structuredContent` carries the URLs as CPSC stores them.
- **A CPSC provider-failure error row gets one retry, then surfaces as retryable `upstream_error`** ([#20](https://github.com/cyanheads/cpsc-recalls-mcp-server/issues/20)). It was non-retryable `upstream_rejected`; the retry resends the query with `format` moved last, missing CPSC's per-query-string cache of the failed row. Other error rows stay non-retryable, with no retry.
