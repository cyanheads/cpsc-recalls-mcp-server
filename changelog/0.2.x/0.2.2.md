# 0.2.2 — 2026-10-08

## Added

- **Integers sent for string fields are repaired to their digits before validation** (mcp-ts-core 0.13.9). `cpsc_get_recall` accepts `recall_number: 25043` and treats it as `"25043"`; it was rejected before.
- **Numeric strings sent for number fields and `null` at an optional argument are repaired before validation** (mcp-ts-core 0.13.14). `days: "3"` is read as `3`, and `null` drops the key so the argument's default applies; both were rejected before.
- **A tool error's `structuredContent.error.data` carries `requestId`, and its `content[]` text closes with `request <id>`** (mcp-ts-core 0.13.10).

## Changed

- **The three tools no longer forward their declared recovery hints by hand.** The framework fills a declared `recovery.hint` from the definition's `errors[]` (mcp-ts-core 0.13.10), so error results carry the same hints as before. No client-visible change.
- **Dockerfile installs production dependencies in a `deps` stage pinned to `$BUILDPLATFORM`** (mcp-ts-core 0.13.10). The stage cross-installs for the target architecture, so a multi-arch build no longer runs Bun under QEMU, and those installs pass `bunfig.toml`'s release-age gate and security scanner. Musl-only packages are pruned from the glibc image (0.13.11); `scripts/install-otel.ts` and `scripts/prune-musl-packages.ts` are new. `ENV MCP_FORCE_CONSOLE_LOGGING` is removed from the image.
- **Bun 1.4.0 → 1.4.2** in `packageManager`, the Docker base images, and the README badge (0.13.7).
- **`server.json` npm entries drop the `run start:*` package arguments and use `runtimeHint: "npx"`; the `streamable-http` entry sets `MCP_TRANSPORT_TYPE` to `http`** so a registry client starts the HTTP transport (template fix from 0.13.11).
- `.gitignore` and `.dockerignore` ignore every `.env*` file (`.gitignore` keeps `.env.example`, `.env.template`, `.env.sample`); `.dockerignore` also excludes the MCP Registry token files. `.mcpbignore` excludes `docs/idea.md`, `logs/`, `.cache/`, and `tests/` from the bundle. `package.json` `files` excludes `dist/*.mcpb` from the npm tarball.
- `.env.example` and the README configuration table document `LOG_TOOL_FAILURE_PAYLOADS`; `.env.example` also documents `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES`, `LOG_LLM_INTERACTIONS`, `MCP_REQUEST_STATE_KEY`, and the per-signal OTLP endpoints.
- README jurisdiction lists name firearms (ATF) among the agencies outside CPSC's scope, and the capability reference for the three tools is condensed. The MCP SDK badge reads `^2.2.0`.
- Description punctuation in `server.json`, the `Dockerfile` image label, and `CITATION.cff`: an em dash becomes a colon.
- The CodeQL workflow analyzes `actions` and `javascript-typescript` in separate jobs, each uploading under `/language:<language>`.
- `CLAUDE.md` and `AGENTS.md` update the framework and MCP SDK versions, the context table, and the error-contract text.
- Framework skills under `framework-skills/` and the `scripts/` helpers (`devcheck`, `lint-mcp`, `lint-packaging`, `release-github`, `check-framework-antipatterns`, `check-skill-versions`) are resynced with the framework; `lint:packaging` gains a Dockerfile build-platform check and `release-github` a `--check` flag.
- The framework releases between 0.13.7 and 0.13.14 also carry their own security fixes; see the [mcp-ts-core changelog](https://github.com/cyanheads/mcp-ts-core/tree/main/changelog).
